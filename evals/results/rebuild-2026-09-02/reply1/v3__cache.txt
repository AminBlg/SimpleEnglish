The stale reads come from the Redis cache not being invalidated when prices update. When you write a new price to the database, the old value stays in Redis until its TTL expires — up to 10 minutes if that is your TTL setting. Reads hit Redis first and never see the database until the key expires.

The fix is to invalidate (delete) the affected Redis key immediately after every successful price write, before you return a response. Most codebases do this in the service layer: write to the database, then call `DEL price:<id>` on the cache. The next read will miss cache, fetch the fresh price from the database, and repopulate Redis. If you need stronger guarantees, use a write-through pattern instead: write to Redis and the database together in the same operation, so the cache is always current.
