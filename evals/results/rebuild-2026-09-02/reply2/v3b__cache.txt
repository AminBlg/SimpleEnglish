The staleness comes from your cache-aside pattern: when a price updates in the database, the existing Redis key is not invalidated, so readers keep getting the old value until the TTL expires (presumably set to 10 minutes or more).

The fix is to delete (or update) the Redis key at the same time you write the new price to the database. Wrap both operations in the same service call so they always happen together. If you update the key rather than deleting it, use a pipeline or Lua script to make the write atomic and avoid a race where a concurrent reader repopulates the stale value between your delete and the next database read.

If you need stronger guarantees, switch to a write-through pattern: every price write goes to Redis first, then the database, so the cache is never stale by definition.
