sqlpipe uses a reader process that streams Postgres rows in batches. The reader connects to the database and fetches rows with a configured query. Rows accumulate in a buffer until the batch size threshold is reached. A converter transforms the batch into Parquet row groups with columnar layout. The converter applies schema mapping and data type conversion during transformation. An uploader writes multipart objects to S3 with retry logic for error handling. Each component runs independently to process the data flow without manual intervention. The system scales horizontally by adding more reader instances to increase throughput across the cluster. Monitoring tracks batch counts, conversion rates, and upload status metrics continuously in real-time. Alerts notify operators when processing latency exceeds thresholds or failures recur.
