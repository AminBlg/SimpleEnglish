## Troubleshooting

**Connection timeouts.** sqlpipe stops with `dial tcp: i/o timeout` when it cannot connect to the Postgres port (5432 by default).

1. Make sure that the host that runs sqlpipe can connect to port 5432. A firewall or security group usually blocks the connection.
2. If the database is managed (RDS, Cloud SQL), make sure that the instance accepts connections from the IP of sqlpipe.
3. If the network is slow, increase `source.connect_timeout_seconds` in the config.

**S3 permission errors.** sqlpipe stops with `AccessDenied` when the IAM identity does not have the permissions that it needs.

1. Make sure that the IAM identity has the `s3:GetObject`, `s3:PutObject`, and `s3:ListBucket` permissions for the bucket that you use.
2. If the bucket uses a policy, make sure that the policy allows the IAM identity to perform these actions.
