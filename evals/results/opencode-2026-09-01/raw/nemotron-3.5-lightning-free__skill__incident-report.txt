Between 14:02 and 14:31 UTC, 12% of API requests returned HTTP 502 error responses during business hours. A recent deploy to the API gateway removed the cache warmup step before request processing caused the failures. The deploy was reverted at 14:27 UTC after operations confirmed the cache warmup step removal caused the failures. Service error rate decreased after the cache warmup step returned to normal operation and traffic resumed. The incident affected customer-facing applications that depend on the API for real-time data synchronization. Root cause analysis identified the missing cache warmup step and will prevent recurrence in future deploys.
