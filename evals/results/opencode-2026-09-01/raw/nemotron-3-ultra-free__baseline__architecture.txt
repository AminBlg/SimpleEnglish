sqlpipe streams Postgres data to S3 as Parquet through three decoupled processes. The **reader** connects to Postgres, executes a query, and emits row batches via a bounded channel — backpressure prevents memory spikes on large tables. The **converter** consumes batches, accumulates rows into Arrow record batches, and flushes them as Parquet row groups with configurable row-group size and compression (ZSTD default). Each row group is written to a temporary file. The **uploader** picks up completed row-group files, streams them to S3 using multipart upload with exponential-backoff retries and part-level checksums. On success, it deletes the temp file; on permanent failure, it leaves artifacts for manual recovery. A coordinator orchestrates the pipeline, handles graceful shutdown (draining in-flight batches), and emits progress metrics. All components run as independent goroutines/processes communicating over channels, enabling horizontal scaling of converter and uploader stages.
