**Troubleshooting**

**Postgres connection timeout.** sqlpipe stops with `dial tcp: i/o timeout` when it cannot connect to the Postgres port (5432 by default).

1. Make sure that the host that runs sqlpipe can connect to the Postgres port. A firewall or security group usually blocks it.
2. If the database is managed (RDS, Cloud SQL), make sure that the instance accepts connections from the IP of sqlpipe.
3. If the network is slow, increase `source.connect_timeout_seconds` in the configuration.

**S3 permission error.** sqlpipe fails with `AccessDenied` when it cannot read or write the S3 bucket.

1. Make sure that the AWS credentials have the `s3:GetObject` permission for the source bucket.
2. Make sure that the AWS credentials have the `s3:PutObject` permission for the target bucket.
3. If you use a bucket policy, make sure that the policy allows the principal that runs sqlpipe.
4. If the bucket is in a different region, set `target.region` in the configuration.
