**Troubleshooting Connection Timeouts and Permission Errors**

sqlpipe stops when it cannot connect to the Postgres port or access S3 storage. Follow these steps to find and fix the problem.

1. Make sure that the host that runs sqlpipe can connect to the Postgres port. A firewall or security group usually blocks it.
2. If the database is managed (RDS, Cloud SQL), make sure that the instance accepts connections from the IP of sqlpipe.
3. If the network is slow, increase `source.connect_timeout_seconds` in the configuration.
4. Make sure that the S3 access key and secret key are correct in the configuration.
5. Make sure that the IAM user or role has permission to access the target S3 bucket and objects.
6. If you get an error about denied access, check the S3 bucket policy and the attached permissions.
7. Make sure that the system time is correct on the host running sqlpipe, as S3 uses time-based authentication.
