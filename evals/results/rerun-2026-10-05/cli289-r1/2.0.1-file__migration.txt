A backfill is a one-time data operation that writes a value into the new column for every existing row, because the database cannot satisfy NOT NULL on rows that were inserted before the column existed.

The migration hangs because adding a NOT NULL column without a default forces the database to rewrite all 20 GB of rows in a single transaction while holding an ACCESS EXCLUSIVE lock, blocking every read and write on the table for the duration.

The safe pattern is three separate migrations. First, add the column as nullable with no constraint. Second, run a batched UPDATE to fill in the value in chunks (e.g., 1 000–10 000 rows at a time with a small sleep between batches) so you never hold a long lock. Third, once every row has a value, add the NOT NULL constraint — on Postgres 12+ you can do this with `ALTER TABLE t ALTER COLUMN c SET NOT NULL` after creating a `NOT VALID` check constraint and then validating it, which avoids a full table lock.

Kill the hanging migration first (`SELECT pg_cancel_backend(pid)` in Postgres), then apply the three-step approach above.
