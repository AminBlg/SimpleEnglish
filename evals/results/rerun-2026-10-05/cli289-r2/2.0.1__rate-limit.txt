A token bucket is a counter that refills at a steady rate and drains by one each time a request arrives. Each user gets their own bucket with a maximum of 100 tokens. The bucket gains tokens at 100 per minute (roughly 1.67 per second), and any request that arrives when the bucket is empty is rejected. Because the bucket can hold up to 100 tokens, a user who was idle can burst up to 100 requests instantly before the limit kicks in.

For your case this fits well. The 100-requests-per-minute requirement maps directly to the refill rate, and the burst behavior is usually acceptable for API users who have been quiet. The main alternative, a fixed window counter, is simpler but lets users double-burst at window boundaries (100 requests at 11:59 plus 100 at 12:00). The token bucket avoids that problem.
