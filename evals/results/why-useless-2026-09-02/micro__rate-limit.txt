A token bucket works like a jar that refills with tokens at a steady rate — in your case, 100 tokens per minute, or roughly 1.67 per second. Each incoming request consumes one token; if the jar has tokens, the request goes through, and if the jar is empty, the request is rejected or queued. The jar has a maximum capacity (the "bucket size"), which controls how much burst traffic a user can send before hitting the limit. This fits your use case well because it allows short bursts (a user can fire 100 requests at once if they have not used the API recently) while still enforcing the 100-per-minute average over time. The main implementation choice is whether to store per-user token counts in Redis with a timestamp, which is the standard approach for distributed systems.
